# Settings

Two JSON files, the repo's first: `<repo>/.smithy/config.json` (this repo only) and
`~/.smithy/config.json` (your defaults). In a linked worktree the repo file is the main
checkout's, so one setting holds for every worktree. You never edit them by hand:

- **use-smithy setup** asks everything up front, or each skill asks a setting the first time it
  needs it and saves your answer;
- `smithy config list` (in any skill's `scripts/`) shows each setting, its value and where it came
  from; `smithy config set [--repo] <key> <value>` changes one and `smithy config unset [--repo] <key>`
  puts it back to the default.

| Setting | Default | What it does |
|---|---|---|
| `models.<harness>.<tier>` (tier `cheap`, `mid`, `strong`; `smithy config list` shows them as `models.<tier>` for the current harness) | ask | Stored per harness in your user config only (`smithy config set-model <tier> <name>`); smithy ships no model names, so the first skill that needs a tier asks you to name it. The router (`smithy route`) picks a tier per task: cheap for small, mechanical or read-only work, mid for most features, strong for risky, hard or large work and the last fix round. |
| `models.<harness>.judge` (`models.judge` in the list) | unset (falls back to the strong model) | Optional fourth tier (`smithy config set-model judge <name>`): the model `smithy consult` uses for a decision's one-call pick; unset, consult uses `strong`. |
| `agent.effort` | `medium` | Reasoning effort for every agent smithy starts (`smithy agent`, `smithy consult`, warden workers): `low` or `medium`. It is also the cap: `high`, `xhigh` or `max` run at `medium`. Passed as `--effort` (Claude Code) or `-c model_reasoning_effort` (Codex) and as `$AGENT_EFFORT`; CLIs without an effort flag keep their own default. Speed (`fast`/`normal`/`full`) adds agents, never effort. |
| `ask.timeout` | `10` | Minutes an agent waits for your answer to one of your decisions (use-smithy's stop list) before one `smithy consult` call picks. `0` = no timer: wait. Never applies to the hard floor. Auto-decisions go to `smithy decisions` (`~/.smithy/decisions/<owner>-<repo>.md`, from origin; the folder name without one); `smithy decisions pending` lists the ones you haven't kept or changed. |
| `agent.timeout` | `90` | Minutes before `smithy agent` (warden workers, `--bg` runs too) kills the agent's whole process group (Unix; on Windows only the agent process), logs "timed out after Nm" and exits 124; `0` means no limit; a value that is not a number warns and uses 90. `--timeout <min>` overrides it for one run. |
| `route.domain` | unset | Comma list of the product's own nouns (`secret` for a secret scanner) that never count as risk for `smithy route`. |
| `warden.worker_model` | `route` | `route`: a tier per task; `session`: the parent's model; or one model name for every worker. |
| `tasks.commit` | ask (no default: smelt `plan` asks once) | `true`: commit specs and tasks (`docs/specs/`); `false`: keep them out of git (`.docs/specs/`). |
| `tasks.ignore` | ask (no default: asked once when `tasks.commit` is false) | `gitignore`: a committed `.gitignore` line; `exclude`: `.git/info/exclude` (this machine only). |
| `tasks.location` | `repo` | `repo`, `local` (`~/.smithy/plans`) or `board` (an external tracker: GitHub Issues, Linear, Jira; not `smithy board`). |
| `warden.merge` | unset (warden asks once per batch) | Merge mode only. Unset: warden asks once per batch in its plan line (auto or manual); `auto`: warden merges green PRs (workers never merge); `manual`: warden lists each green PR for you. A value you save counts as your words, except for the production branch (use-smithy **Merges**: only your yes). |
| `warden.cleanup` | `auto` | End finished workers and remove their worktrees and branches without asking; `ask`: warden asks before ending them. |
| `warden.stuck_minutes` | `15` | Minutes without a worker heartbeat before a working item counts as stuck. |
| `warden.max` / `warden.mode` | `5` / `smelt normal` | Parallel workers; the speed of the one check wave warden runs on the whole batch (`smelt fast`, `smelt normal`, `smelt full`) or `plain`. Workers always build at `fast`. |
| `tend.watch` / `tend.label` | `prs` / `agent` | What `/tend watch` follows (comma list of `prs`, `issues`, `actions`, `base`, `alerts`, or `all`); the issue label it may queue. |
| `stack.<key>` | unset | A command `smithy stack` can't detect (`stack.test`, `stack.single`, `stack.lint`, `stack.dev`…), set with `--repo`. Read from the default branch's committed config or the main checkout's local file, never a branch's own edit. |
| `decide.url` / `decide.model` | unset (off) | Optional decision model for `smithy decide`, on once both are set. A URL ending in `/scores` uses Respan's behavior format; anything else System One (Jev, Kev local, Clef, span-02). `decide.key_env` names the env var with the key (never the key), `decide.timeout` is in ms (3000). Three failed calls in a row set `decide.enabled` false; set it `true` to turn it back on. |
| `auto.sources` | `github` | Comma list of issue sources `smithy auto` polls: `github`, `linear`, `board` (the built-in tracker, harness build). |
| `auto.mode` | `labeled` | `labeled`: only issues with the `auto.label` label; `all`: every issue that passes the source's filters. |
| `auto.label` | `auto` | Label that opts an issue in (`auto.mode labeled`). |
| `auto.model_prefix` / `auto.speed_prefix` | `model:` / `speed:` | Label prefixes for the worker tier (`model:cheap`…) and the smelt speed (`speed:fast`…). |
| `auto.max_per_day` | `20` | Issues launched per local calendar day; the rest stay queued (an `auto.hours` window across midnight can launch up to 2x this overnight). |
| `auto.max_cost_per_day` | | USD of reported agent cost per local day. At or over it `smithy auto serve` starts no new orchestrator until tomorrow and records `cap_reached`; workers already running finish. Only cost a CLI reports counts (Claude Code today); runs with unknown cost (codex, opencode, killed or timed-out runs) count as 0. Empty = no cap. |
| `auto.hours` | unset (always) | Launch window `HH:MM-HH:MM` in local time (`22:00-07:00` wraps midnight). |
| `auto.every` | `60` | Seconds between polls of each source. |
| `auto.paused` | `false` | `true` holds `smithy auto take`: nothing launches until it is `false` again (`p` in `smithy tui`). |
| `daemon.port` | `7477` | Loopback port of `smithy daemon`'s API (harness build). It never listens beyond `127.0.0.1`. |
| `daemon.allow` | empty | Comma list of Tailscale logins allowed through `tailscale serve` (the `Tailscale-User-Login` header). Empty: only the local token (`~/.smithy/daemon.token`). |
| `auto.merge` | `manual` | Merge mode for auto batches; the production branch stays yours (use-smithy **Merges**). |
| `auto.agent` | unset (the CLI `smithy agent` detects) | Agent CLI for `smithy auto serve`'s orchestrator: a name (`claude`, `codex`, `opencode`…) or an absolute path to one (the kind comes from the file name), or `pool` for any harness in `smithy pool`. It and every worker it starts run with `smithy agent --profile auto` (passed on in `SMITHY_AGENT_PROFILE`), never a full bypass. Claude Code: permission mode `dontAsk`, allowed Read/Edit/Write/Glob/Grep, listed git subcommands (fetch and push only to origin, `worktree list` only), `gh pr|issue|run` read and comment commands, go/npm tests and smithy by its absolute path; denied `git -c`/`git config`, `--upload-pack`/`--receive-pack`/`--exec`/`--repo`/`--output` and URL push targets, every shell redirect (`>`) and `tee` (files are written with Edit/Write), `gh api|auth|gist|alias|extension`, `smithy auth|config|pool`, curl, wget, reading keys (`~/.ssh`, `~/.config/gh`, `~/.aws`, `~/.smithy/auth.json`, `~/.smithy/accounts`) and editing hooks, shell rc files and settings. Codex: workspace-write sandbox, network on, approvals off, so it has no guard against sending data out. `smithy doctor` runs `<cli> --version` and warns when it is missing, not headless, or codex. Run serve under a dedicated user with least-privilege tokens. |
| `auto.sandbox` | `off` | Isolation for unattended workers (`--profile auto`) on top of the allow-list: `off`, `native` or `container`. Every `auto.sandbox*` key is read from your user settings only, never a repo's `.smithy/config.json`, and a user settings file that can't be read stops workers too. It fails closed: when the sandbox can't start (including a claude older than 2.1.331, the version these settings were verified on), the worker is not started (`smithy agent` exits 1) and serve launches nothing (logged, `orchestrator_failed` event to the TUI and Telegram). The orchestrator itself is **not** sandboxed (sandboxes don't nest) and stays on the allow-list only, so repo tests it runs go unsandboxed; every worker it starts is sandboxed. **native**, Claude Code: `--settings` turns on its sandbox (Seatbelt on macOS; bubblewrap + socat on Linux) for Bash and its children with `failIfUnavailable`, `allowUnsandboxedCommands: false`, `network.strictAllowlist` and `allowedDomains` github.com, api.github.com, api.anthropic.com, api.linear.app plus `auto.sandbox_domains`; shell writes only to the worktree, its git dir, `~/.smithy/plans`, `~/.smithy/warden` (the worker's `GOCACHE` is `~/.smithy/warden/gocache/<worktree>`) (and the system temp dir, which the sandbox always allows); `--add-dir` is narrowed to those plus the skills roots, which are write-denied; reads denied for `~/.smithy/auth.json`, `~/.ssh` (except git's SSH signing `.pub`; signing goes through ssh-agent), `~/.aws`, `~/.netrc`, `~/.git-credentials`, `~/.gnupg`; writes denied for hooks, git config, `.claude` and smithy config. On macOS `enableWeakerNetworkIsolation` is on by default (`auto.sandbox_weaker_net`) so `gh` can verify TLS; it opens the system TLS trust service to the worker, and turning it off breaks `gh` inside workers. SSH commit signing goes through your ssh-agent, so a worker can sign commits as you: use a dedicated signing key. On Linux, signing inside the sandbox is not supported. The worker env still carries your `GH_TOKEN`: use a fine-grained, repo-scoped token. File tools (Read/Edit/Write) run outside the sandbox and stay under the allow-list. Add hosts your tests need (e.g. `proxy.golang.org`, `registry.npmjs.org`) to `auto.sandbox_domains`. GPG signing (`~/.gnupg`) does not work inside it. **native**, codex: workspace-write with network off, so push and gh fail inside the worker (doctor warns). Other CLIs: use `container`. **container**: `docker` (else `podman`) `run --rm -i --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp --pids-limit 512 --memory 4g` (`auto.sandbox_memory`) `--network` from `auto.sandbox_network`, which is required: unset or `none` refuses to start (claude needs its API and git needs to push); `proxy` puts workers behind smithy's egress proxy (see `auto.sandbox_network`); `bridge` is open egress with no domain allow-list, with the worktree, git dir (its `hooks` and `config` mounted again read-only), plans and warden dirs mounted at the same path, `HOME=/tmp`, the host uid on Linux (podman: `--userns=keep-id`), and only these env names passed: the `AGENT_*` run variables, `SMITHY_AGENT_PROFILE`, `WARDEN_HARNESS`, `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `OPENAI_API_KEY`, the proxy variables, and `GH_TOKEN` only from `SMITHY_SANDBOX_GH_TOKEN` (a scoped token; the host's own GitHub token never passes). Model credentials are scoped to the harness: claude gets `CLAUDE_CODE_OAUTH_TOKEN`/`ANTHROPIC_API_KEY`, codex `OPENAI_API_KEY`, opencode none (its free models need no login) unless its model names the `anthropic/` or `openai/` provider; every other credential name is dropped. When the env lacks them they come from `smithy auth` (`claude`, a token from `claude setup-token`; `anthropic`; `openai`). The value is never on argv or in smithy's logs, but container env is visible to `docker inspect` and to anyone with access to the engine socket. A worker whose harness needs a credential and has none is refused (a Keychain login never reaches the container; claude's fix: `claude setup-token`, then `smithy auth set claude`). On macOS the container runs as root inside the engine's VM (no `--user`; caps dropped, read-only root); on Linux it runs as your uid (`--user`). With `DOCKER_HOST` unset, the docker context's socket is used when it exists, else the first of `~/.kiri/run/docker.sock`, `~/.orbstack/run/docker.sock`, `~/.colima/default/docker.sock`, `~/.docker/run/docker.sock`, `/var/run/docker.sock`; the docker binary is found on PATH or at `~/.kiri/bin/docker`, `~/.orbstack/bin/docker`; doctor prints the engine and socket. Podman is unchanged. The image carries claude-code and OpenCode 2.4.0; OpenCode has no smithy allow-list under `--profile auto` (it runs `--auto`), so for it the container is the isolation. Live-tested on macOS with Kiri and `opencode/big-pickle` (no login): worktree writes work, writes to `/etc` and the host home fail (read-only root), `~/.smithy/auth.json` is absent, `git status` works. `smithy pool` account dirs are read- and write-denied to a native worker's shell; a container mounts only its own run's account dir and passes only that account's config-dir variable. With `auto.agent pool`, native checks every harness in the pool (claude accounts need claude 2.1.331+) and an unreadable `pool.json` stops workers; under `container` each claude account needs its own token (`claude setup-token` as that account, then `smithy auth set claude:<account>`; the shared `claude` token is not used), and doctor fails until every claude account has one. `smithy doctor` checks what the mode needs. Under `native`, git reaches GitHub over HTTPS with gh's credential helper; SSH remotes don't work inside it. |
| `auto.sandbox_domains` | unset | Comma list of extra hosts a `native` worker, or the container egress proxy (`auto.sandbox_network proxy`), may reach. |
| `auto.sandbox_image` | `smithy-sandbox:latest` | Image for `container`; build it with `docker build -t smithy-sandbox:latest sandbox/`. |
| `auto.sandbox_network` | unset | `--network` for `container`, required: unset or `none` refuses to start (claude can't reach its API, git can't push). **`proxy`** (recommended): workers join `smithy-internal`, a `--internal` network with no route out, and reach the outside only through the `smithy-proxy` sidecar (on `smithy-internal` and its own `smithy-egress` network, not the shared `bridge`, and no published port; read-only, no capabilities, running `smithy proxy serve` from the linux binary in `auto.sandbox_proxy_binary` with only `~/.smithy/auth.json` (read-only) and `~/.smithy/proxy` (its own events: asks, approvals, refusals, merged into the TUI's log) mounted; never the accounts, plans, warden or config; workers mount neither). The sidecar starts on the first worker and restarts when its hosts, binary or `auth.json` change (so a new `smithy auth bind` reaches it). Egress: `CONNECT` on port 443 only to GitHub (`github.com`, `api.github.com`, `codeload.github.com`, `uploads.github.com`, `objects.githubusercontent.com`, `raw.githubusercontent.com`), the model APIs (`api.anthropic.com`, `api.openai.com`, `chatgpt.com`, `opencode.ai`, `*.opencode.ai`, `models.dev`), the package registries (npm, Go proxy and sumdb, PyPI) and `auto.sandbox_domains` (`*.example.com` for subdomains); everything else, plain HTTP included, is refused and logged (`proxy_denied` event in `~/.smithy/proxy/events.jsonl`). Secrets: a key stored with `smithy auth set <name>` and bound with `smithy auth bind <name> <host> [METHODS] [--header H] [--prefix P]` is sent by the proxy, never to the worker: the worker calls `http://smithy-proxy:8877/s/<name>/<path>` (`/s/<name>@<host>/<path>` when bound to several hosts), and the proxy forwards it over HTTPS to the bound host with `H: P <key>` (default `Authorization: <key>`), dropping any `Authorization`, `Cookie` or API-key header the worker sent. No TLS interception and no redirects followed. Methods default to `GET,HEAD`; any other method is refused unless bound, or, with `smithy auth ask <name> on`, held as a `secret_ask` event (name, method, host and path, shown to you only; one waiting per secret, others get 429) until `smithy proxy approve <id>` (`deny <id>`), else refused (403) after 5 minutes. The key (raw, URL-escaped or base64) is replaced with `[secret:<name>]` in the response's headers and body (`Set-Cookie` dropped); the log keeps kind, host, method, name and status only. The worker env gets `HTTPS_PROXY`/`HTTP_PROXY` (and lowercase) and `SMITHY_PROXY` set to the sidecar, `NO_PROXY=smithy-proxy`, and its prompt says how to use `secret:<name>`; claude workers may run `curl http://smithy-proxy:8877/s/...` (other curl stays denied). `bridge` is open egress with no domain allow-list (doctor warns); `host` is refused (it shares the host's network). The default image carries Claude Code and OpenCode only: other harnesses need an image of your own in `auto.sandbox_image`. Live-tested on macOS with Kiri. |

## GitHub access

smithy reaches GitHub (open, merge, verify and watch PRs, read CI runs) in one of three modes;
`smithy doctor` says which one it found:

| Mode | When | What works |
|---|---|---|
| `gh` | the GitHub CLI is installed (and signed in, or no token is set) | everything; the best experience |
| `token` | no gh (or gh signed out) and `GH_TOKEN` or `GITHUB_TOKEN` is set | everything, over the GitHub REST/GraphQL API; owner/repo come from the `origin` remote |
| `none` | neither | git only: `smithy pr create` pushes and prints the compare URL to open the PR by hand (a non-GitHub `origin` exits 3: no PR opened, branch not pushed); `pr merge`, `pr-state`, `verify` and `wait` on PRs exit with "needs the GitHub CLI or GH_TOKEN" |

The token goes only in the `Authorization` header to `api.github.com`, or to `https://<GH_HOST>/api/v3`
when `GH_HOST` names a GitHub Enterprise host; it is never printed, logged or written to receipts.
`smithy pr merge <pr> [--rebase|--merge|--squash]` merges through whichever mode is active, so
skills don't need to call `gh pr merge` themselves.
