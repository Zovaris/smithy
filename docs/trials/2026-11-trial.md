# smithy trial, 2026-11

A first-time run of the skills from `origin/release/next` (d949269), extracted with `git archive` and
installed into a throwaway repo. The binary was built from the same commit and used through
`SMITHY_BIN`. This report's own branch is cut from `release/next`. The session that ran the trial
was created from `main`, but it read no skill text from `main`.

## Setup

- Sandbox: `~/Codes/smithy-trial`, a Go CLI (`tab split <cents> <people>`) with tests. `origin` is a
  local bare repo, so nothing was pushed to a real remote and GitHub PRs were impossible.
- Models (`~/.smithy/config.json`): cheap = haiku, mid = sonnet, strong = opus. Top session: opus.
  `agent.effort` was medium.
- `decide` was off (no `decide.url`). Only one call reached it: the extras-01 worker ran
  `smithy decide rules`, which exited 3 and printed nothing. Nothing failed because of it, but
  nothing documents what exit 3 means here.
- Token counts: "instruction tokens" means the skill text loaded (SKILL.md, references and agent
  prompts, chars/4). "Run tokens" is the sum of the `subagent_tokens` the harness reported per
  agent. The top session's own tokens are not included, because the harness does not report them
  per run.

What the numbers say:

- **The cost is one ~50–58k floor per subagent, whatever its prompt.** Agent prompts are 270–1,000
  tokens; the rest is harness system prompt, tool schemas and file reads. Trimming skill text saves
  little. Each subagent that is not launched saves about 55k.
- The cheap-model estimate (10k/19k/46k) was close for instruction tokens (10k/12k/17k measured)
  but measured the wrong thing: real cost is about 51k / 219k / 497k, set by the agent count
  (1 / 4 / 9).
- `normal` and `full` found real issues only through **one** agent each. The normal adversary found
  negative cents accepted (exit 0). The full spec-check found criterion 5 only partly tested. The
  second full adversary, the property agent, the security reviewer and every second look found no
  new defect.
- The fast spec-check (51k) caught a wrong README claim. It was the best value per token in the trial.

## Friction

Unclear, contradictory or stalling points, with where they showed up.

1. **A non-GitHub remote is in no branch of SHIP.md.** `smithy pr create` pushes, then fails
   (exit 1) with gh's raw "no known GitHub host" error and no smithy hint. SHIP covers "no remote" and "no gh/token", not
   this case. All four shipping agents improvised (`state=ready note=no-github-pr`). `smithy doctor`
   still said `ready`, although warden SKILL.md says doctor fails when ship items can't open PRs.
2. **Headless workers fail silently.** In the desktop app, `claude` isn't on PATH
   (`smithy agent: claude: command not found`). With a symlink it started but logged
   `Not logged in` with `is_error: true`, and `smithy agent` still returned a pid. Cards stayed
   `queued`; warden would only have noticed after the 45-minute stale window. `doctor` didn't check
   either. Workers were rerun as in-session subagents (given a pointer to the brief file, not its
   full text: a deviation from harness.md).
3. **Desktop spawn is impossible in a launched session.** This trial ran in a session another
   session started, so `start_session` is refused (harness.md says so for event turns). warden
   offers no "propose cards" path for a whole batch launched from such a session.
4. **`smithy config set --repo` writes an untracked `.smithy/config.json` in the worktree.** Two
   effects: (a) every later `smithy receipt run` in that worktree is `dirty` ("commit, then run it
   again"), so the full run's ship receipts can't be fresh without committing a config file; (b) the
   setting lives in one worktree, so the main checkout asked `tasks.commit` again.
5. **Two spec locations.** SKILL.md puts chat criteria in `.smelt/spec.md`; SPEC.md and TASKS.md
   use `smithy task-dir <slug>` (which then stops to ask `tasks.commit` and `tasks.ignore`). It's
   unclear which to use at `normal` with no plan.
6. **Test-agent cleanup contradicts itself.** TESTING.md says to remove agent worktrees with
   `smithy cleanup`. It refuses them, because they carry the WIP commit ("has commits not on any
   remote; push it or pass --force"), and it printed `kept` although it had removed the worktree
   and kept only the branch. Every run ended in a manual `git worktree remove --force` and
   `git branch -D`.
7. **Holdout receipt can't be clean in a warden worker** (extras-01). Agent tests go in `zz_*`
   files in the worker's tree, so the holdout runs dirty, and VERIFY says a dirty receipt is valid
   only for the red step.
8. **TDD.md leaks this repo into the skill.** "their seam is the repo's doc lint (here
   `bash tests/skills.sh`)". extras-03 looked for `tests/skills.sh` in the user's repo.
9. **`smithy names branch` guesses the type badly.** "split json output" became `refactor/…`, the
   CONTRIBUTING task `feat/03-contributing-doc`, and this report `feat/…`. Every docs item in the
   trial got a non-`docs` type.
10. **Read-only reviewers can't see receipts.** The full second look couldn't confirm the 10s fuzz
    receipt ("not in the repo"), so a "partial" stayed half-open. Receipts need a path reviewers can
    read, or `smithy receipt list` in the reviewer's allowed commands.
11. **"It runs" only fires with a `dev` line.** `smithy stack` showed `dev: none` for a CLI, so
    VERIFY's row didn't apply literally. I ran `go run ./cmd/tab …` under a receipt anyway. The
    rule should say "a run command, or the binary's main path".
12. **Hostile and mutation never ran.** Hostile runs only at full and only "with something that
    runs"; mutation needs a tool, and Go had none (`mutation: none`). The CLI part ran at normal, so
    no run combined the two. Neither the speed table nor the stack line says how to get hostile
    coverage for a CLI change at normal.
13. **Strict TDD vs reality.** I (the top session) wrote the whole parser after one red test, and
    the remaining tests passed first time: the anti-pattern TDD.md names. Nothing in the flow
    catches it. `guard-tests` is optional and wasn't installed.
14. **Brief vs smelt on test agents** (extras-02): the brief says "the speed's test agents"; smelt
    fast says "none for a feature". The worker read that correctly, but only after a pause.
15. **Card states aren't listed in the brief** (extras-03 tried `state=running`). There is also no
    PR URL for the closing line when no PR exists (02, 03).
16. **`smithy receipt run` with no `--`** prints only usage, and SKILL.md never shows the `--` form
    (extras-03).
17. **Reviewer base vs given SHA** (extras-01): the agent files say
    `merge-base origin/<base>`, the worker passed a SHA, and both reviewers flagged the mismatch.
18. **Grill and approval gates** at full stop for the user 5–6 times (why, approaches, design,
    decisions, seams, how to run). In this trial they were self-answered. For a well-specified money
    function, that many stops is heavy.
19. **The spec-check "wrong" verdict pushed a spec edit after agreement** (normal): the fix widened
    criterion 2's wording, and the second look rightly said "the user should confirm". RECEIVING.md
    doesn't say whether changing an agreed spec to close a finding needs the user.

## What couldn't run

- **tend**: `smithy pr-state` and `smithy wait watch:all` both exit non-zero with "none of the git
  remotes … point to a known GitHub host". That is correct and clear; tend says up front it needs
  GitHub.
- **PRs, `smithy verify`, `smithy pr merge`**: no GitHub host. Branches were pushed to the local bare
  origin: `docs/document-split-usage`, `feat/split-json-output`, `feat/parse-amount`,
  `feat/01-add-tip`, `feat/02-version-command`, `feat/03-contributing-doc`. None were merged (merge
  manual).
- **`smithy wait batch:extras`** worked well without GitHub: it woke once per card that reached
  `ready`, at no token cost.
- **mutation**: no Go mutation tool (`smithy stack`: `mutation: none`), so not applicable, as the
  skill says.
- **hostile**: the full-run change has no runnable entry point, so it didn't apply.

## Recommendations, in order

1. Fix friction 1, 2 and 4 first: they are correctness bugs in the binary (a raw gh error where a no-GitHub path is needed, silent
   worker death, self-dirtying receipts).
2. Then optimizations 1–5. Agent count is where the tokens go.
3. Fix route rule 6 before the next warden batch. It decides which model a worker gets.
