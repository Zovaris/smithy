# smithy trial 2, 2026-11

A first-time run of the skills from `release/next` (dde2360) on real work in a real GitHub repo
(`Zovaris/claude-mods`, a set of Claude desktop mods). The binary was built from the same commit
and used through `SMITHY_BIN`. Goals: check trial 1's fixes, run the real PR and tend flows, and
measure the new costs. `decide` stayed off. This report's branch is cut from `release/next`.

## Setup

- Work: (1) usage-bar shows stale usage, (2) context-meter is stale too, (3) review cache-control
  and the other mods for bugs and add the missing tests. The repo had no CI.
- Flow: `smelt plan` (questions self-answered from the code), then `warden` (smelt normal, merge
  manual, max 3) on the five task files, then `tend` watching `prs,actions`.
- Models (`~/.smithy/config.json`): cheap = haiku, mid = sonnet, strong = opus; `agent.effort`
  medium. Top session (planner + warden): opus.
- Token counts, as in trial 1: "instruction tokens" = skill text loaded (chars/4); "run tokens" =
  the `subagent_tokens` the harness reported per agent. A worker's figure excludes its nested
  agents, so per-worker totals add the two. The top session's own tokens are not included.

What the numbers say:

- **One smelt normal run's subagents now cost 114–150k for a feature** (adversary + one combined
  reviewer), against **219k** in trial 1 (adversary + spec-check + standards + second look). The
  combined reviewer and "one second look per round" fixes did what they were meant to: 2 agents
  instead of 4.
- **The per-agent floor rose from ~55k to ~73k** (12 nested agents, 55–122k). Agents here read
  real code (a 842-line register.tsx, a 25k-line engine type file), not a toy CLI. Agent count still
  sets the cost, but the floor depends on the repo.
- **Review-and-fix tasks ran a third agent** (regression, ~70k each). 04 and 05 were reviews
  with fixes, so the workers counted them as bug work. Neither regression agent found anything
  the adversary had missed.
- **Per worker: ~293k average, against ~189k in trial 1** (566k / 3). The tasks were much larger
  (real mods, a 388-line diff in 04) and every worker ran normal, while two of trial 1's three ran
  fast. Workers' own context, 79–154k, grew with the task, not with skill text.
- **The adversaries found real bugs in 2 of 5 runs.** In 03, a NaN measured value. In 05, a
  regression the worker had introduced (`npm install --frozen-lockfile` became `bun add
  --frozen-lockfile`). The reviewer found real issues in 02 (a store-read failure that deleted another session's
  reading) and 03 (comment policy). The builder check (106k) earned its cost: it caught that a single
  `lastWindows` store key could never hold a cross-session max, and that `session.measure` fires
  only at turn end.

## Friction

1. **Workers couldn't be spawned the documented way.** This session was started by another
   session, so `start_session` was refused for all six launches. The headless path failed too: `claude -p`
   (bundled CLI, not on PATH) is `Not logged in`, and the desktop's auth is host-provided. I ran the
   five workers and tend as background subagents, giving each a pointer to its brief file rather
   than the full text, which deviates from harness.md. This is trial 1's friction 2 and 3,
   unchanged. `smithy doctor` said `ready` both times.
2. **Desktop: a subagent's completion ends the turn, and spawning is refused in event turns.** The
   builder check had to run before tasks were written. Its answers arrived in a turn that couldn't have
   spawned workers even with the session path working, so I appended them to the task files
   after writing them.
3. **`smithy wait batch:` loops** on a manual `ready` card (stage `verify`): it woke 3 times for
   item 01 alone, so I stopped re-arming it and relied on subagent notifications.
4. **Routing** misread prose three times (optimization 5); I overrode all three, as models.md allows.
5. **`smithy stack` found nothing** (`lang: unknown`, `test: none`) in a TS repo whose tests run
   through `claude plugin test`; there is no way to tell it.
6. **Re-review has no step** (RECEIVING): 02 resumed its reviewer by hand. The reviewer still
   listed a finding as open because it checked before the fix commit. The fix shipped unreviewed; the warden read it instead.
7. **Test-agent worktrees vs the brief** (01, 03, 04, 05): each improvised (`zz_` files, temp dirs,
   scratch copies); 04's adversary file was lost on worktree removal.
8. **Card states**: worker 01 set `state=done` (not a state) before `ready`. Workers also put
   their whole report in `note`, which floods `smithy cards board`.
9. **CI-first ordering** isn't modelled: the batch had one item that every other PR needs for checks.
10. **tend's waits**: `smithy wait --every N --max M` heartbeats returned within seconds, not after
    the window. Foreground `sleep` is blocked, so tend built its own Monitor loop to get a real deadline.
    It also recorded `checks: none` as "ready with ci=none", which was right, though the recipe would call it green.
11. **Spec placement with warden**: specs in `.docs/specs` are out of git, so worktrees don't have
    them; briefs had to point at the main checkout's absolute paths. intake.md doesn't say this.
12. **Undocumented test-double shapes** (03, 04): `session.measure` must return `{changed}`,
    `turn.step` a `{turnId, index, answer, toolUses}` async iterable. Both were found by trial and
    error. This is a claude-code gap, not a smithy one.
13. **Spec drift**: 02 changed `fmtPct` although the spec said no change was needed there. It
    recorded this under "Decided without you". That is right, but the reviewer had no rule for it
    (trial 1 friction 19, from the other side).
14. **`smithy commit`** rejected subjects over 72 characters twice; the style output doesn't say so.
15. **A `smithy cards set` call hung for 120s once** (03) and was moved to the background; it didn't recur.

## Recommendations, in order

1. Friction 1–3: a launch path that works from a launched desktop session (subagent workers as a
   documented adapter, and doctor that checks it), and a `wait batch:` that can be re-armed.
2. Optimizations 1 and 5: the regression agent and routing are the largest avoidable costs left.
3. Optimizations 7 and 10: an unreviewed fix and `checks=none` as green are correctness gaps.
