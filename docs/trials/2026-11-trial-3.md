# smithy trial 3, 2026-11

A first-time run of the skills from `release/next` (7fbf00d) on a project built from nothing:
`leakscan`, a TypeScript CLI that finds leaked secrets in a folder and in git history, in a new
private repo (`Zovaris/leakscan`) with real GitHub Actions CI. The binary was built from the same
commit and used through `SMITHY_BIN`. `decide` stayed off. Goals: measure cost after ADR 0008's
cuts, collect every agent's skill feedback, and check with planted bugs whether the agents ADR 0008
left out of `normal` (a separate standards reviewer, a second adversary, security at full) are still needed.

## Setup

- Flow: `smelt plan` (questions self-answered) into 5 tasks, then `warden` (smelt normal, `full`
  for the detector, merge auto into `main`, not production), then `tend watch prs,actions` until
  the batch ended. After that, a planted-bug check (below).
- Models (`~/.smithy/config.json`): cheap = haiku, mid = sonnet, strong = opus; `agent.effort`
  medium. Top session (planner + warden): opus.
- Counting, as in trials 1 and 2: "instruction tokens" = skill text loaded (chars/4); "run
  tokens" = the `subagent_tokens` the harness reported per agent (a worker's figure excludes its
  nested agents, so per-task totals add both). The top session's own tokens are not included.
- Workers again ran as **background subagents** with a pointer to their brief file: `start_session`
  was refused (this session was started by another session), as in trial 2.

What the numbers say:

- **Agent count still sets the cost; the floor is back to ~55–65k on a small repo** (trial 2: ~73k
  on real code). 27 nested agents in the batch, 52–85k each. Skill text is ~11k per worker, under 2% of a task.
- **ADR 0008's normal (adversary + one reviewer) only happened once (01).** Every other task is
  "risky" by smelt's definition (input parsing, file access, secrets), so normal added security,
  and the speed table's "property … mutation on core logic" added two more. A normal task here cost
  **370–506k with 3–6 agents**, not 114–150k. In a security tool every task is risky, so `normal` is close to `full`.
- **The one full run cost 758k, 2× the average normal task** (9 agents, two review rounds).
- **Wall time is the dependency chain, not the agents.** The batch took 62m and the critical path
  01 → 02 → 04 → 05 took ~60m. Each task's active work was 9.5–20m.

The slow parts are the adversary (3–6 min when it writes many tests, and its findings drive the
fixes) and the waits for prerequisites. CI is 23–31 s per run. Review is 1.5–3 min.

**What could have run in parallel with a different split.** The plan was 01 → {02, 03} → 04 → 05.
04 and 05 both had to wait because both edit `src/cli.ts` and consume 02 and 03's code. Two better splits:

1. Split 05 into `src/git.ts` (`scanGitHistory`, blocked only by 02's `Finding` type) and a small
   wiring task after 04. The git reader (10m of test agents and fixes) would then run alongside 03/04, cutting ~15m.
2. Fold 01's skeleton into the plan commit (package.json, CI workflow, tsconfig), then start
   02, 03 and git.ts together. The critical path would be about 02 → 04 → wiring, about 35m, not 60m.
   warden can't do either: it takes the plan's `Blocked by` as given, and TASKS.md's self-review
   checks collisions but not the critical path.

## Planted-bug check

A fresh sonnet subagent that saw none of this work planted three defects on `trial/planted-review`
in two plausible commits ("support include of a shared allowlist file", "tidy slack token
pattern"). The suite, typecheck and lint stayed green. It wrote an answer key I read only after scoring:

- **D1 spec violation (detector):** `slack-token` regex `xox[abprs]-` → `xox[bprs]-`, so `xoxa-` tokens are missed (AC2).
- **D2 repo-standards break:** a runtime dependency (`strip-bom`) replacing a one-line BOM check,
  against AGENTS.md "No runtime dependencies" and the spec decision.
- **D3 security flaw:** a new `include:` allowlist directive whose targets are not checked against the
  scan root, so a file outside it is read and applied (path traversal, AC8). Its first bad line is echoed to stderr.

`smelt review` + `smelt test` ran on the branch at both speeds (shared agents are counted in both):

| Agent (model) | Speed | D1 xoxa | D2 runtime dep | D3 traversal |
|---|---|---|---|---|
| spec-check + standards, one reviewer (haiku) | normal | ✓ AC2 `wrong` | ✓ decision `wrong` + standards `should` | ✓ AC7/AC8 `wrong` (read, not run) |
| security (haiku) | normal + full | ✓ medium | ✓ low | ✓ **high**, plus stderr leak and include fan-out |
| adversary 1 (sonnet) | normal + full | ✓ failing test | ✓ medium (static) | ✓ failing tests (`../`, symlink, absolute) |
| property (sonnet) | normal + full | ✓ counterexample | ✗ | ✓ counterexamples (path, symlink) |
| mutation (sonnet) | normal + full | ✗ (rules.ts 35/35 killed) | ✗ | ~ include code has no coverage, `isInside` mutants survive; no traversal named |
| spec-check (haiku) | full | ✓ `wrong` | ✓ decision `wrong` | ✓ `wrong` |
| standards (haiku) | full | ✓ `should` | ✓ `should` | ✓ `should` |
| adversary 2 (sonnet) | full | ✓ failing test | ✓ low | ✓ failing tests + content leak in the error |
| hostile (sonnet) | full | ✓ repro | ✓ medium | ✓ **high** repro in folder and `--git` modes, `/etc/passwd` line on stderr |

Verdict for ADR 0008's deferred cuts:

- **Every defect was caught at normal by at least four independent agents**, three of them with a
  failing test or repro. The full-only agents (separate standards reviewer, second adversary,
  hostile) found **no defect the normal set missed**. Their only extra detail, outside-file content
  leaking through the error message, was also in normal's security report. Running full cost +168k (492k vs 324k) for nothing new here.
- **The combined reviewer did not weigh standards less.** It flagged D2 under both reports, the same
  as the separate standards reviewer. ADR 0008's "Bad" consequence did not show.
- **But no standards finding is blocking in this repo.** Both standards reviewers rated D2 `should`,
  because `standards.md` makes only `docs/agents/STANDARDS.md` violations blocking and the repo has
  none. Its rules live in AGENTS.md, which smelt itself reads. D2 was blocking only through
  spec-check, because the spec happened to repeat the rule as a decision.
- Caveats: the diff was small (2 commits, ~90 lines) and all three defects sat in it, so this tests
  recall on an obvious diff, not on hidden bugs. Mutation can't catch a spec change by design. Security
  ran at normal because the diff touched file access; on a non-risky diff, normal has no security agent.

## Agents' skill feedback

Collected from every agent's `skill feedback:` line (27 batch agents, 5 workers, tend, the builder, 10 planted-check agents). Grouped, with counts:

**smithy commands**
- `smithy receipt run` takes argv, not a quoted string; the first try failed in 4 of 5 workers. Receipts taken on a dirty tree are hidden from `receipt list`, so 01 and 05 reran checks.
- `smithy commit` refuses when files are already staged (after smelt's `git reset --soft` flow), and rejects subjects over 72 chars only when it runs (01, 05).
- `smithy wait-turn` returns exit 4 after a few minutes, and the harness moves a call to the background after 180s. Workers looped it by hand for up to 42 minutes, so 05's wait cost many turns (all 4 waiting workers). The brief's "never poll" rule conflicts with this.
- `smithy scan` flags test-fixture keys; SHIP.md doesn't mention `smithy:allow` (04, 05; this repo is all fixture keys).

**smelt agent files**
- `standards.md`: no fallback when `docs/agents/STANDARDS.md` is missing (blocking is then impossible); "ledger's comment policy" has no path; it requires `<smithy> comments` while the caller says read-only, and gives no `<smithy>` path (one reviewer built its own binary). Raised by 6 reviewers.
- spec-check, standards and security have no status block, though the report contract asks for "its status block" (4 agents).
- `spec-check.md`: unclear whether to check ACs the diff doesn't touch, how to mark prose decisions, or whether lockfiles count toward the 400-line advisory.
- `mutation.md`: no machine-readable reporter, so the `tail`-cut clear text hides survivors (5 of 5 mutation agents reran or parsed JSON). No rule for NoCoverage, timeouts or "likely equivalent" in the score.
- `adversary.md`: no rule for performance findings or timing assertions; "don't read the implementation first" is awkward when the helper style lives in the tests, or when the spec is silent on a feature the diff adds (5 adversaries). No baseline-run step.
- `property.md`: no empty-findings report shape; unclear whether example tests may sit in a property file.
- `security.md`: unclear whether "high" is blocking, whether to check against the spec, and where non-class findings go (dependencies, sizes).
- `hostile.md`: "build output in scratch" conflicts with `npm run build` writing an ignored `dist/`; the 5-cycle rule is vague for a diff review.
- `builder.md`: the 300-word cap is tight at 16 criteria; unclear whether security defaults like fail-closed are minor or theirs.

**smelt flow**
- A worktree per test agent is heavy for pure-function modules: `node_modules` must be symlinked, `smithy cleanup` refuses dirty worktrees, and WIP commit → soft reset is awkward after a merge commit (03).
- The harness forced 02's handback while its second-look reviewer ran asynchronously, so the worker couldn't finish its review loop until the warden resumed it.

**tend**
- No recipe for a PR already merged when read, or a wait that exits with no event line; `pr:` with a full URL isn't shown; "one line per event" vs a full report under hush; `<skill-dir>/scripts/smithy` vs `SMITHY_BIN` precedence not stated.

| # | Where | Change | Saves |
|---|---|---|---|
| 1 | `smelt/SKILL.md` speed table, ADR 0008 | Apply the deferred cut: at full, one adversary and one combined spec-check+standards reviewer; hostile only for long-running services. The planted check found nothing the normal set missed. | ~170k per full run (≈ the 168k measured) |
| 2 | `smelt/SKILL.md` speed table | At normal, cap test agents at adversary + **one** of property/mutation (mutation for rules or parsers, property for pure functions). Today, in a repo where every task is risky, normal runs 4–6 agents. | ~60–65k per normal task (3 of 4 here) |
| 3 | `agents/standards.md`, `REVIEW.md` | When `docs/agents/STANDARDS.md` is absent, the rules in AGENTS.md / CLAUDE.md are blocking. Give the `<smithy>` path, and say `comments` is allowed. | correctness: D2 was non-blocking in every standards report |
| 4 | `smithy wait-turn`, worker brief | Block until go (or for `--max`), not a few minutes, and say how long. Show one foreground loop in the brief. | dozens of wake turns per waiting worker (05: 42m) |
| 5 | `TASKS.md` self-review | Add a critical-path check: split the longest chain so a pure module (here git.ts) doesn't wait for wiring tasks; fold the skeleton into the plan commit. | ~25m of 62m wall here |

| 7 | `smelt/SKILL.md` Always, SHIP.md | Show `smithy receipt run --claim <c> -- <argv>`, the staged-files and 72-char rules of `smithy commit`, and `smithy:allow` for fixture secrets, once each. | 1–2 failed calls per worker (all 5) |

| 10 | `TESTING.md` | Test agents run in the foreground of their worker, or the worker waits for every async reply before its final report. | a forced handback and a resume (02) |

## Friction

1. **Workers still can't be spawned the documented way** from a launched desktop session
   (`start_session` refused). I used harness.md's subagent fallback without trying headless
   `smithy agent` first, so that the harness would report each worker's tokens. Workers got a pointer to the brief, not its full text.
2. **The auto-mode classifier denied `smithy pr merge`** for 01 and 03 despite merge auto. The cards said
   `merge-blocked`, and the warden verified and merged, as acting.md says. `smithy doctor` warned about
   this up front. #59 (warden merges every green PR, landed during this trial) addresses it.
3. **Routing keyword false positives** (optimization 8): `package-lock` → "risky: lock".
4. **The builder check found real gaps** (PEM bodies tripping high-entropy, lockfile noise, `--git` on a
   subdirectory, execFile's 1 MiB maxBuffer). Four "theirs" questions were answered by taking its
   recommendations, so it earned its 65k again.
5. **No standards finding can block** without `docs/agents/STANDARDS.md` (optimization 3).
6. **The worker brief's `smithy` path vs `SMITHY_BIN`:** the brief had to tell every agent to set
   `SMITHY_BIN`. One planted-check reviewer didn't get it and rebuilt smithy from source.
7. **An idle wait isn't free:** each waiting worker read hush, smelt and its brief (~58–61k context)
   before `wait-turn`. That is the harness floor, paid once, so it's not waste, but a worker launched
   long before its turn holds a slot and a subagent.
8. **Decisions made alone that matter for a secrets scanner:** 04 made unreadable paths fail open
   (skip with a warning; `--strict` proposed). 05 reads the default `.leakscanignore` from the working
   tree in `--git` mode, so a contributor can hide historical secrets from CI. Both are in their PR bodies under
   "Decided without you" and in warden's decisions.md; neither reached the user as a high-impact
   decision, although security is "always high" in smelt's Always section.
9. **Remote branches** of merged PRs are left behind (optimization 9).
10. **A worker set `phase=ready` on a merged card**, and notes hold whole reports, which floods `cards board` (trial 2 friction 8, unchanged).

## Comparison with trial 2 and ADR 0008

| | Trial 2 | Trial 3 |
|---|---|---|
| Per-agent floor | ~73k (real code) | ~55–65k (new small repo) |
| Normal task, agents | 2 (adversary + combined reviewer), 3 with regression | 2–6: risky tasks add security, property, mutation |
| Normal task, total | 193–410k | 223–506k |
| Full task | n/a | 758k (9 agents) |
| Merges | manual, none merged | auto; 3 by workers, 2 by warden after classifier denials |
| Planted bugs | none | 3 of 3 caught at normal; full added nothing |

ADR 0008 holds: the combined reviewer and one second look per round cost less and lost nothing.
Its "Bad" consequence (a combined reviewer may weigh standards less) did not show with a planted
standards break. Its deferred cuts (one adversary at full, security at full only when risky) are
supported: the second adversary and the separate reviewers found nothing extra. The new cost driver is
`normal` on risky code, where the speed table's conditional agents turn 2 agents into 4–6.

## Recommendations, in order

1. Optimizations 1 and 2: take ADR 0008's deferred cut at full, and cap normal's conditional test agents. These are the two largest costs left (~170k per full run, ~60k per risky normal task).
2. Optimization 3 and friction 8: standards must be able to block when the repo's rules live in AGENTS.md, and security decisions made alone should reach the user.
3. Optimizations 4 and 5: `wait-turn` that really waits, and a critical-path check in task splitting. Together they would cut the 62m batch to ~35m.
