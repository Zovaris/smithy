# Trial 6: smithy's recommended flow vs no smithy (2026-11-21)

Same leakscan spec. A: one session, no smithy. B: use-smithy → smelt, taking its own advice:
`normal`, `build all` here (3 tasks, chain of 3), no implementer subagents, one check wave
(adversary, reviewer, security). Both arms ran as subagents of one session.

| | A | B |
|---|---|---|
| Wall time | ~6 min | ~30 min (build 6, check 6, fixes and re-reviews 9, planted check 7) |
| Tokens | ~160k (session ~89k + planter ~72k) | ~1.16M (session ~163k + 11 subagents ~1.0M) |
| Planted defects | 3/3, 0 false positives | 3/3, 0 false positives |
| Real bugs left on main | 5 known, self-reported (UTF-16 columns, `diff.noprefix`, merge commits, EACCES aborts, TOCTOU) | fixed: glob ReDoS, git paths with spaces/quotes/tabs, fingerprint line flagged, PEM hiding lines; found and left: git evasion via a lone `\r` (high), quadratic JWT regex |

## Findings

1. The check wave finds real, serious bugs (a high-severity scan evasion) that a single session
   doesn't. That is smithy's value.
2. Its cost was the re-review loop: three rounds (~520k tokens), one of them a resumed reviewer
   that re-sent its old report. Each round found a new edge in the last fix and never converged.
3. Check agents cost 80–135k each on real code, not ~60k.
4. Speed wording made a secret scanner read as `full`; `smithy comments` flagged the
   `smithy:allow` markers `smithy scan` asks for.

## Changes

Re-review capped at two rounds with a fresh reviewer when a resume echoes; open findings after
that go to the user or "Decided without you"; risky adds security without raising the speed;
`smithy comments` ignores `smithy:allow`; `build all` commits each build; `Spec:` may point at an
existing spec.
