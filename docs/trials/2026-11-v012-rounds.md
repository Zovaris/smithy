## R4 detail (reports B and C)
- B: build ~4 min, check wave ~2.7 min, fixes + 2 re-review rounds ~3.2 min. Real bugs fixed
  with tests: JSON without `message` matched metadata, a plain line lost its second word, years < 100 mis-parsed, bad offsets and
  bare-number `--since` accepted, nanosecond epoch crashed `--json`, level forms unparsed, CI
  token without `permissions`.
- C: skeleton PR then core PR, check + fix + ship ~4.7 min; fixed an out-of-range epoch that
  aborted the file. The planted-branch review found two more real bugs left on main (stdin `-`
  twice, years 0–99 mapped to 19xx).
- Per-agent cost: 70–130k each; the reviewer runs on haiku, adversary and security on sonnet.

## Findings
1. smithy's value is the real bugs its check wave finds and fixes before merge, not planted-bug
   detection: plain sessions catch 3/3 plants too.
2. `fast` costs about what a plain session does.
3. warden only pays for big, independent tasks; small ones lose time to merge churn.
4. Sonnet follows the skills as well as Opus at similar time and tokens.
5. The trials ran the released v0.11.0 binary through the launcher, so this release's Go
   changes were not exercised (the "unknown option --speed" frictions came from it).

## Frictions fixed after R4
Re-review covers every spec-check row that was missing, partial or wrong plus Standards
blocking, reads the exact commit sha, and closes a departure recorded as an open risk as
"deferred to user"; read-only agents ignore `zz_*` files; `zz_` files move to the system temp
dir; adversary expected values are re-derived; declined holdout tests may be dropped; another
ref is reviewed in a detached worktree; rebase-proof uses the no-tests flag and runs only for
more than one source commit; `status=done pr=` lands in a follow-up commit; `tasks add`
defaults to `Speed: fast`; check `smithy commit`'s exit code; single-file runs skip pretest hooks.

## R5 (csvkey, `SMITHY_BIN` = the release branch build)
A hidden 20-case suite graded each arm. A missed a trailing blank line (exit 3); B and C's check
waves caught it (C kept it as a ruling). B fixed a BOM-broken header, `"a"b` accepted, EPIPE,
terminal escapes in errors and CI token permissions; C fixed invalid UTF-8 merging keys, `"a"b`
and CI permissions. Cost: A 63k, B 99k, C 105k main-session tokens, plus the check agents.
C's `unknown option --speed` came from a call without `SMITHY_BIN` (the v0.11.0 binary).

## R6 (durpy, Python, branch binary)
A plain Sonnet and smithy `fast` on Haiku both passed 47/47 hidden cases; Haiku also fixed a
28-digit Decimal round-trip bug and non-ASCII digits. smithy `normal` on Sonnet failed 2: its
adversary flagged that `format` must emit weeks, and the builder declined it as spec-ambiguous
though the spec lists `w`. It fixed CPython's 4300-digit limit and raw input in error messages.

## R7 (splitcents, full vs normal vs plain)
All three passed 34/34 hidden cases (float traps, max-safe amounts). `normal` fixed a stack
overflow over ~125k participants, control characters in names, unbounded BigInt input and CI
token scope. `full` fixed float-parsed CLI weights (lost exact ties), 400-digit weights
overflowing, C0 and C1 control characters, EPIPE and CI scope; its hostile agent found the C1
and EPIPE bugs. Property and mutation were skipped (no library), now property runs without one.
`full` cost ~1.3x `normal` in time. Every arm's first CI was red on `node --test <dir>`.

## R8 (ratelim, Go; plain Sonnet vs normal Haiku vs full Sonnet)
All passed 10/10 hidden tests (burst, refill, AllowN atomicity, Reserve debt, cancelled Wait,
concurrency, backwards clock, extreme rates). Haiku at `normal` fixed a 64 KiB line crash, a
backwards-clock free token and ignored write errors; `full` (11.5 min) fixed a 1 ns early token
(adversary) and SIGPIPE exit (hostile); property held over 4000 cases. Plain: 2–12 min, 29 tests.

## R9 (semverq, TypeScript; Haiku plain vs normal vs full)
All passed 55/55 hidden cases. Plain Haiku: 6 min, 177 tests, self-checked against node-semver.
`normal`: 12.8 min, fixed hyphen ranges inside AND sets, an over-broad catch and CI test glob.
`full`: 12 min, fixed non-string input, EPIPE, control bytes on stderr and loose operator
spacing (hostile found three). Every arm hit `tasks add --speed`: a real CLI bug, now fixed.

## R10–R11
smithy's value shows most with vague or security-heavy work: on shortlnk the batch check found
three bugs the hidden suite did not grade, and on a vague idea the plain arm accepted malformed
amounts that smelt's own spec and check wave closed. warden's own feedback (no `smithy brief`,
tend not used as a skill, `wait` doesn't wake on CI) is logged for later.

## R12 (hookrelay, warden with subagent workers)
warden finds the most bugs (11 real ones, a 6to4 SSRF bypass among them) but costs ~8x the time
on a 4-task spec. Frictions fixed after: brief task-file specs and rulings, the batch waiter's
start-of-wait reports, the subagent wait-turn loop and the `waiting` closing line.

## R13 (kvlog, warden + tend)
First round where tend ran as a skill. warden cost ~5x the time of plain on a 4-task spec.

## R14 (invoicer, warden on bug issues)
On clear bug reports smithy matches plain. Its debug path wasn't used by warden workers: fixed
after (route: debug, red-first `receipt check-red`, risky items get the security agent).

## R15 (notesapi, warden on a risky brownfield task list)
smithy stops on security decisions when nobody can answer: safer, but it delivers nothing for that task.
Plain builds a safe variant instead.
