# Trial 7: recommended flow after the re-review cap (2026-11-21)

Same leakscan spec and setup as trial 6 (both arms as subagents of one session).

| | A: no smithy | B: smithy, recommended flow (`normal`, `build all` here, one wave) |
|---|---|---|
| Wall time | ~5 min | ~16 min (build ~5, check ~3.5, fixes + 2 re-review rounds ~2.5, ship ~1, planted check ~3.5) |
| Tokens | ~153k (session ~84k + planter ~69k) | ~875k (session ~166k, build wave ~369k with resumes, planted check ~340k) |
| Planted defects | 3/3, 0 false positives | 3/3, 0 false positives |
| Real bugs | 7 known gaps left, self-reported | fixed before merge: lone CR broke git parsing, `-diff` attributes hid history, unterminated BEGIN hid the file, entropy skipped on overlap, allowlist error echoed a secret, CI token scope; one more found after and left open (the allowlist file is exempt from all findings) |

## Findings

1. With the re-review capped, smithy costs ~3x the time and ~6x the tokens of one plain session
   on a project this size, and its check wave fixed six real bugs before merge; the control left
   seven known gaps of its own (different ones), so neither ships clean.
2. Planted-bug detection is no longer a differentiator: both arms catch 3/3 when each plant
   deletes its own test. A harder plant set is needed to separate them.
3. Frictions fixed: regex literals read as comments; a combined reviewer that dropped its
   standards report; re-reviews repeating advisory items; agents touching session tools;
   `build all` PR count unstated.
