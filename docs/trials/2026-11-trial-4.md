# Trial 4: A/B, leakscan with and without smithy (2026-11-20)

The same spec (a TypeScript secret-scanning CLI: detector, allowlist, folder walker, git history,
CLI) was built twice from scratch in two fresh private repos, then the same kind of three defects
was planted in each and reviewed. Smithy at `release/next` afc0e2a.

| | A: no smithy, one session | B: smelt plan + warden, `normal` per task |
|---|---|---|
| Wall time | ~11 min | ~31 min |
| Tokens | ~180k (session ~122k + planter ~59k) | ~1.82M |
| PRs | 2 merged | 6 merged |
| Agents | 1 (planter) | 21 (6 workers, 11 check agents + 3 resumes, planter, 3 reviewers) |
| Tests | 119 (unit, properties, Stryker 94.6%) | ~150 |
| Planted defects caught | 3/3, 0 false positives | 3/3 blocking, 0 false positives, a few extra true findings |

Where B's tokens went: per-task check agents ~897k, workers ~493k, the planted-bug wave ~246k,
the warden ~181k. The chain 01 → 05 → 06 set the wall time; task 05 alone took ~15 min.

## Findings

1. Quality was the same. One capable session reviewing its own diff caught what the agent wave
   caught. Per-task check agents were the largest cost and found nothing a single wave would miss.
2. Splitting a CLI-sized spec into six tasks bought no time: the chain was nearly linear.
3. Friction in B: route sent lockfile and secret-scanner text to the strong tier; vitest ignored
   `zz_*_test.ts`; cleanup left remote branches; `wait-turn` in the background can't wake a
   subagent worker; no `Speed:` line in the task template; `smelt plan` re-ran its plan phases on
   an agreed spec; the adversary's brief handed it bodies it shouldn't read first.
4. A's own miss: rule tests covered two of five Slack prefixes, so a dropped prefix passed.

## Changes

- Warden workers build at `fast` (no agents); warden runs one check wave on the whole batch at
  its speed after the merges, and one `fix` item for blocking findings.
- `build all` checks each task itself and runs the speed's agents once, on the whole branch; three
  tasks or fewer are built without implementer subagents.
- Task lists are as small as works; smelt recommends building here unless two independent tasks
  are each over ~15 minutes.
- The frictions in finding 3 and the rule-test variant rule (TESTING.md).
